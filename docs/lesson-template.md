# Lesson authoring template

Replace instructions with teaching; never publish empty sections. Consolidate headings when appropriate.

```text
# ID — concrete capability
## Learning objective
Observable actions and runtime/compiler assumptions.
## Prerequisites
Linked stable IDs; why each is needed.
## Explanation and mechanism
Plain explanation, analogy and its limit, accurate mechanism.
## Examples and execution trace
Small example, expected result, trace, realistic application.
## Alternatives and common mistakes
Failure, reason, correction, trade-offs, non-use case.
## Interview preparation
Natural short answer; deeper follow-up; linked questions.
## Practice
Recall, implementation, debugging, design; separate solutions.
## Revision
Distinctions and closed-book questions.
## Completion criteria
Unseen task, independent explanation, tests, delayed recall.
## References
Primary sources and versions.
```

Diagrams must explain a relationship or execution order. Read arrows as claims and verify them. Label browser and Node models separately.
